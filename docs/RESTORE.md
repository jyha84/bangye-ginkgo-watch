# 실행과 복원

## 1. 백업 확인

`BACKUP-MANIFEST.json`은 파일별 SHA-256과 원래 Sites 소스 커밋을 기록합니다. 인증키·런타임 환경변수 값·CCTV 영상·사용자 사진·Git 인증 정보는 포함하지 않습니다. 운영 환경의 키는 이 소스 백업과 별도로 관리해야 합니다.

## 2. HTML만 실행

루트 `index.html`을 사용합니다. 인터넷이 연결되어 있으면 사진 색 분석·3D·날씨·지도 링크를 사용할 수 있습니다. CCTV는 지도에서 확인합니다.

카카오맵의 현재 위치는 HTTPS 또는 브라우저가 신뢰하는 로컬 환경에서 위치 접근을 허용해야 사용할 수 있습니다. 위치를 거부하면 출발지 직접 선택 링크를 사용합니다. 네이버 지도는 모바일 앱의 현재 위치를 사용합니다.

## 3. GitHub Pages에 정적 버전 올리기

원한다면 GitHub 저장소의 Pages 설정에서 `main` 브랜치의 루트 폴더를 게시 대상으로 선택합니다. 이 백업 자체는 Pages나 자동 배포를 켜지 않습니다. 계정 요금제·저장소 공개 범위에 따라 Pages 사용 가능 여부를 먼저 확인하세요.

루트 HTML은 외부 CCTV API 키를 요구하지 않습니다. 정적 페이지에 실제 키를 붙여 직접 ITS를 조회하는 방식으로 바꾸지 마세요.

## 4. 기존 Sites의 전체 기능 복원

1. 복원하려는 사이트가 `https://bangye-ginkgo-watch.bzbone.chatgpt.site/`인지 확인합니다.
2. `.openai/hosting.json`이 해당 Sites 프로젝트와 연결되는지 확인합니다.
3. 서버 비밀값 `ITS_API_KEY`가 설정되어 있는지 확인합니다. 실제 값은 채팅·코드·로그로 꺼내지 않습니다.
4. `web/`, `worker/`, `scripts/` 원본으로 빌드·검증합니다.
5. 기존 사이트의 공유 범위를 보존하면서 완성한 버전을 게시합니다.
6. 실제 CCTV 재생과 휴대폰 지도 앱 연결은 직접 확인합니다.

Sites에 제공한 런타임 비밀값은 GitHub에 자동 백업되지 않습니다. 새 환경에서는 키를 다시 등록해야 합니다.

## 5. 다른 새 사이트로 이전

복제본의 기존 Sites 프로젝트 ID로 게시하면 원래 사이트를 갱신할 수 있습니다. 새 사이트를 만들 때는 새 프로젝트에 연결하고, 필요한 런타임 비밀값을 별도로 설정합니다. 별도 Worker 호스팅을 사용한다면 해당 환경이 `fetch(request, env)` Worker ESM, Web Crypto, 외부 HTTPS 요청을 지원하는지 확인해야 합니다.

## 6. 이후 수정 순서

1. `web/` 또는 `worker/` 원본 수정.
2. 해당 변경에 맞는 테스트와 빌드 실행.
3. 독립 HTML 내보내기를 다시 실행해 루트 `index.html` 갱신.
4. 변경 파일과 Markdown 문서를 함께 커밋.
5. GitHub 백업과 실제 사이트 게시는 별개이므로, 운영에 적용하려면 Sites에도 게시.

자동 동기화 워크플로는 이 백업에 포함하지 않습니다.
